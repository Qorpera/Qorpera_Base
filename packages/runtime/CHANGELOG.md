# Changelog

## [Unreleased]

### Breaking Changes

- A folder-v2 file wake's payload is `qorpera.folder-file-wake/v1` (`schema`, `seq`, `commitId` equal to the wake's source id, at most 21 `changes` of `{path, op, version, priorVersion?, from?}` with `from` only on a `move_in`, and `more` up to 1000), parsed as closed (folder core C4, slice P29b). The snapshot-v1 file wake shape is no longer accepted. The prompt names `wake.payload.changes` and `more`, and the first presence is the first change's path.
- The native host makes every database call through an entry point, with no switch (G2-3bc; `deploy/first-node/RUNTIME-NATIVE-HOST-KEY.md` "G2-3bc"): a job's calls with the job's lease token as G2-2 built them (`QORPERA_NATIVE_HOST_DISPATCH`, `NATIVE_HOST_DISPATCH_DEFAULT` and `nativeHostDispatchMode` are gone), the eight calls it makes between jobs through `qorpera_native_identity_call` with the holder's identity credential (`NATIVE_HOST_IDENTITY_CALLS` replaces `NATIVE_HOST_KEY_CALLS`), and any other call on the project's origin but Storage is refused; an entry point's arguments must be one JSON object. Storage and Realtime keep the key until G2-4. Every native host requires the systemd credential `qorpera-native-identity` (`qorpera.native-identity-credential/v1`); every guest bootstrap's credential list names it and checks it is the guest identity's and independent. A login guest also requires `qorpera-native-identity-state` (its identity's recovery state, read by its gateway) and `QORPERA_NATIVE_LOGIN_GUEST` (`sign_in` or `account_refresh`), and a sign-in's host runs no account loop. An execution reaching an exec slot may carry `native_host.identity_credential`, which replaces the host's for that run; the runner sends its configuration's `native_identity_credential` (a new runner configuration key, with the native bridge only).
- Coding sessions stand by between turns: the guest configuration is `qorpera.coding-command-guest/v4` (its resource profile names only `maxLogBytes`), command requests are `qorpera.coding-command-request/v2` (`timeoutMs` may be null), and guest leases are `qorpera.coding-guest-lease/v2`, one generation per session attachment with the current turn and whether it is open. A new turn no longer stops the session's commands; a new attachment does. The turn context is `qorpera.coding-turn-context/v2` with `commands` (still running, stopped since the previous turn).
- The unreleased office unit now loads credentials from the current boot's immutable directory. Previously acknowledged installations without those files are refused; replay does not backfill missing credentials from the original installation.
