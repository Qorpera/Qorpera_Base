# Changelog

## [Unreleased]

### Breaking Changes

- Coding sessions stand by between turns: the guest configuration is `qorpera.coding-command-guest/v4` (its resource profile names only `maxLogBytes`), command requests are `qorpera.coding-command-request/v2` (`timeoutMs` may be null), and guest leases are `qorpera.coding-guest-lease/v2`, one generation per session attachment with the current turn and whether it is open. A new turn no longer stops the session's commands; a new attachment does. The turn context is `qorpera.coding-turn-context/v2` with `commands` (still running, stopped since the previous turn).
- The unreleased office unit now loads credentials from the current boot's immutable directory. Previously acknowledged installations without those files are refused; replay does not backfill missing credentials from the original installation.

### Changed

- Coding commands have no time, memory, CPU or task limit of their own (the 30-minute maximum, 2 GiB, 200 % and 256 tasks are gone); the agent may still set a deadline, and a command keeps running after its turn. Commit export no longer requires the session's commands to be stopped: it bundles the exact submitted commit.
- The `manage_worker` tool no longer takes an `owner` for a coding session: a coding session runs for the member who asked, on their own account (the kernel refuses any other member, 2026-09-28 "the member who started the work pays").
- Warm conversations (contract amendment 2026-09-27), off unless `QORPERA_NATIVE_WARM_IDLE_MS` is set for the native provider host: after a successful company run the host keeps the opened credential capsule in its private root (pruned to the capsule's own credential files) for at most that window and reuses it for the next run only while the stored capsule is byte for byte the one that root was opened from or last saved as; it readies one spare Codex process for that root. A spare has completed its handshake (artifact pin, auth-only identity, result fence, isolation, configuration and skill checks) and accepts no thread, turn, tool call or provider request until a run is bound; a run with identical process inputs takes it, and every run still uses a process of its own. Codex start-up is split from the run accordingly.
- A native run reaches whichever of the company's Company Computers holds its screen when its route is a company route (`/office/{companyComputerId}/native`). A one-computer route reaching another computer now leaves the run without computer tools instead of failing it. `computer_start` says it may start another machine when every computer on the running machines is in use (a computer is an agent's screen; a machine hosts up to six).
- Warm conversations (contract amendment 2026-09-27), off unless `QORPERA_NATIVE_WARM_IDLE_MS` is set for the native provider host: after a successful company run the host keeps the opened credential capsule in its private root (pruned to the capsule's own credential files) for at most that window and reuses it for the next run only while the stored capsule is byte for byte the one it uploaded last; it readies one spare Codex process for that root. A spare has completed its handshake (artifact pin, auth-only identity, result fence, isolation, configuration and skill checks) and accepts no thread, turn, tool call or provider request until a run is bound; a run with identical process inputs takes it, and every run still uses a process of its own. Codex start-up is split from the run accordingly.
- A company run asks for its context and its wake together, reads its memory profile and both log months together, and runs the two reads of every authority check (run admission and the context read set) together. Every check still runs, and a failure still reports its own stage. The provider service hashes the Codex binary once when it starts, before its run arrives; the session still compares the digest with its pin before it starts Codex, and hashes again if the file changed since (device, inode, size, mtime and ctime in nanoseconds). Reads sent together that lock the same job row share a 10 s budget instead of 5 s each.
- The ephemeral runner service activates its runner before its assignment inbox answers, so a provider that reports a runner ready on a healthy inbox never offers the control plane an inactive runner (which refused the assignment with 423 and cost a retry). A freshly activated runner skips the heartbeat its worker used to send straight after.
- `computer_start` asks which computer to start when the agent calls it, not when the run began (migration `20260928244200`): if other agents took the offered computer's seats meanwhile, placement names another one, a new machine included, so the agent does not wait for a full machine. A request key keeps the computer it was first sent for, so a replay is the same request; with nothing to start at that moment, or a computer the run's route cannot reach, the request names the computer the run was offered, as before.

### Fixed

- Fixed runs whose login is in the vault failing every dispatch when the first provider to acquire them was then refused by the node chooser: that provider's pending runner stayed bound to it, and the preferred node's provider was refused the attempt's runner (23505). Provisioning now gives a pending runner no machine was ever reserved for to the provider acquiring the attempt now, with that provider's activation, and records a registration receipt; a runner with a reservation, active or revoked stays as it is. Migration `20260928235000`.
- A native run saves its credential capsule back only when it changed the login, and only while the store still holds the login the run started from (compared by credential content, read again once on failure); otherwise it keeps the newer stored login, logs that this run's copy was not saved, and does not keep that root warm. Every run used to reseal and upload at the end, so with several runs on one login an older copy could undo a renewal and force a new sign-in. A warm root starts from the stored login's digest, so a renewal made in the kept root between runs is saved by the next run. The check and the upload are two requests, not one atomic write.

- The Co-Founder is told the company formation keys (organization/formation.json: schema, the seven stage keys in order, the one-step and revision+1 rules, statuses), still never to be named to the founder. `company_write` normally refuses a formation write the organization projection would refuse as `COMPANY_FORMATION_REFUSED`, naming the current stage and the one allowed next write, before anything is staged or proposed. That projection only runs when a member approves the proposal, and its refusal never reached the agent.

- The company computer keeps running around agents and members. An agent action whose own page or command work failed and ended (a slow page, a target that never became clickable, a command stopped at its own limit, a password field) no longer closes the screen's browser and is drained like a success, so releasing the screen no longer drains the whole desktop. One authority check that gets no answer (network, timeout, 5xx) no longer ends the desktop, its apps or the agent's session: only a clear refusal, or 30 seconds without an answer, does, recorded as `AUTHORITY_LOST`. The browser relay follows the same rule and, when SQL answers `idle` (nobody entitled present), keeps the window open with its network paused instead of closing it; while idle it asks every five seconds, and a new connection asks at once and waits for that answer. An authority check between an action's steps that gets no answer fails the action as its own instead of closing the browser. A run whose desktop was ended mid-run opens a fresh guest session under the same lease. Expired screen leases that were never released are reaped by the supervisor status.

- The company browser's /tmp is now 1 GiB instead of the 64 MiB other office namespaces keep. With `--disable-dev-shm-usage` all of Chromium's shared memory lives there, so renderers failed allocations and crashed on ordinary sites ("Aw, Snap!", reported as SIGSEGV because the crash handler's `alarm()` tripped seccomp).

- Agents create a Company File folder only as the home for a category of files, named for the category, never on their own just to hold a single file. A folder a member asks for or an assignment names (such as a worker's output folder) is always fine. The run instructions no longer forbid folders nobody requested, and the `COMPANY_FILE_PARENT_MISSING` result and the `company_write`/`company_mkdir` descriptions now tell the model to put a single file in an existing folder where it fits unless a member, its assignment or a category of files calls for the missing folder.
- `company_write` and `company_mkdir` into a folder that does not exist are a definite `COMPANY_FILE_PARENT_MISSING` refusal (denied, `errorCategory` `parent_missing`) that tells the model when to create the folder with `company_mkdir` and repeat the call (see the folder entry above), and never to replace a file to make that folder. SQL refuses it at the check (PT424), before presence and before any bytes are uploaded, and again at prepare and commit. Previously the runner uploaded the bytes, failed while building the candidate tree and reported an unconfirmed, unknown outcome.

- Preserved office startup, supervision, desktop and cleanup failure causes in bounded structured diagnostics. Logs include only allowlisted stages, error codes and categories, never raw messages, credentials, paths or stacks.

- Loaded Chrome for Testing's managed browser policies from its actual Linux path. The browser uses a measured dedicated Bubblewrap copy and enforcing AppArmor profile so Chromium's nested sandbox can start on Ubuntu without changing the shell/desktop profile or granting host capabilities. Browser startup refuses a missing or different enforcing profile when AppArmor is enabled.

- Required exact pending-launch drain confirmation before reporting a screen closed when desktop startup timed out without returning a handle. Registry failure still permits physical cleanup, while unconfirmed private or shared cleanup cannot produce a successful drain.
- Kept screen-lease renewals on their original schedule during frequent authority checks and preserved renewals that became due while a check was in flight. Confirmed renewal alone advances the schedule; expiry, changed identity and revoked access still abort the handle.

- Hashed office effect, startup, capture and export idempotency keys at the SQL boundary to match the fingerprint stored by the native receipt control plane. Tool transport continues to carry the original stable key.

- Kept accepted office continuations waiting during maintenance while the stopped predecessor retains its historical active record. Successor activation delivers once; later restarts preserve delivered activation provenance and recheck current authority.
- Passed an empty environment directly to the protected control child, removing the redundant external environment launcher whose distribution symlink prevented packaged root commands from running. Executable custody, inherited kernel lock and child-process-group cancellation checks remain enforced.
- Admitted private service-owned NAS/adoption ancestors through a descriptor-relative, no-symlink directory walk. State paths still reject foreign owners and writable/shared parents; executable and attestation artifacts retain root-only ownership. The guest unit now lets protected configuration and runtime preflight select the exact adopted roots instead of requiring obsolete fixed directory names.

- Made the Linux browser sandbox probe verify Chromium process ancestry before matching namespace-local renderer PIDs, preventing collisions with independent desktop processes.

- Prevented command and desktop startup cancellation from orphaning Bubblewrap's namespace during its initial fork. A trusted permission gate under Tini delays monitor termination until namespace parent-death cleanup is armed; unknown startup/drain outcomes remain quarantined.
- Prevented browser shutdown from killing Chromium before its persistent cookies were flushed. Network access ends before bounded graceful shutdown; namespace exit remains required before releasing the profile.
- Accepted real browser viewport screenshots within the existing size limits and included their surface/dimensions in receipts. Desktop screenshots still require the fixed display size.
- Prevented viewer disconnect from ending a recovered private browser after readiness, rejected stale private grants before launch, and preserved unexpected private cleanup failures. Screen-open success now waits for physical readiness after receipt admission.
- Kept the service test constructor mock constructible after automatic formatting and ran final regression tests after repository checks.
- Approval cards (auto-review) carry the facts a member decides on, now that the card no longer shows the tool call: a Google Drive file's text (an excerpt) and its name, or its id when nothing names it; a GitHub issue's owner/repository (and `#number` for a comment), title, text and labels; who a group chat invites, by name, the member first (coworkers the context does not list are counted, never shown by id), and its purpose; when a routine runs, in plain words on its own clock (a time without one reads on the wake's clock: a routine run's own zone, else UTC), and a routine named by its key when paused, resumed, removed or ended; a new agent's role, charter and first assignment; and a worker's or coding job's title, goal or follow-up text (naming the worker) and repository (the card read `task`/`instructions`/`brief`, which the worker tool never sends). Quoted text (bodies, typed text, commands, intents, tasks) keeps its lines; any fact cut to its bound is marked `[...]`; C1 controls and bidi overrides read as spaces. Cutting text to its byte bound no longer re-splits the whole string per step, which blocked the run for seconds on a long email body.
- Pointed members to the rules at the bottom of Settings → General (web #360 removed the Rules tab): the `add_review_rule` tool description and the kernel refusal for a full rule list (migration `20260928013400`) no longer say "Settings, Rules".
