# Qorpera cloud client

Shared cloud APIs and wire representations for the web clients. Clients submit intent and display cloud state; they do not execute cloud agent work.

`packages/member-web` now supplies a standalone static application around these APIs, with the Company Computer and account cleanup panels. `MemberCompanyBrowserSession` and `MemberBrowserRecoverySession` are shared browser-safe intent controllers. The packaged web app has passed local Chromium/HTTP/Auth SDK tests with fixture services. Its combined actual SQL/gateway/TLS/private-view proof and hosted acceptance remain open. See the member web README for current web coverage.

`CloudCompanyComputerViews.connectScreen({ binding, mode, signal })` refreshes the selected screen before connecting. An explicit control request submits at most one takeover and waits for the exact epoch's physical acknowledgement. A lost response is never retried automatically; owned pending takeovers can be recovered through fresh status. Private sign-in surfaces use their separate challenge API. The optional `createWebSocket` argument of the member client's `views` factory supports host transports that set their own Origin header; native browsers supply their own Origin.

`QORPERA_OFFICE_VIEWER_ORIGIN` and `QORPERA_OFFICE_VIEWER_CLIENT_ORIGIN` must explicitly match the deployed TLS service and allowed client origin. No default endpoint is assumed. `QORPERA_WEB_OFFICE_TEST_BROWSER` runs the real SQL/TLS/noVNC/Chromium viewer composition with the member web package in `scripts/test-member-office-catalog.mjs` (deleted in the legacy sweep).

`CloudMemberCompanyComputerClient` supplies authenticated member transport for the office APIs. `catalog(signal, after)` discovers the registered office and a bounded page of active agents; it returns the member's management role without exposing infrastructure policy or endpoints. Its `start`, `access`, `signIn` and `views` adapters require the exact company/environment scope. Viewer URLs come from trusted host configuration. Closing a client aborts its activity without stopping the office. Mutations consume observed generations/versions and require refresh after uncertainty. `scripts/test-member-office-catalog.mjs` (deleted in the legacy sweep) verifies SQL discovery and, with `QORPERA_WEB_OFFICE_TEST_BROWSER`, drives the member web package's controls against it.

`CloudMemberCompanyFileClient` is the shared browser-safe member editor. `describe(path)` checks a destination without downloading its contents. `upload({ operationKey, path, expectedVersion, name, mediaType, bytes }, signal)` snapshots explicitly selected bytes, builds the canonical manifest and chunk identities, and submits through current member authority. Files are bounded to 8 MiB; text edits keep their 32 KiB limit. Retain the original operation key, bytes and destination when reconciling uncertain uploads. The API never selects or reads a local path. `pendingFile(target, signal)` verifies a proposed file's length, complete hash and plan-bound response before returning bytes. The web clients use the same protected review API.

`scripts/test-member-company-file-upload.mjs`, which ran these uploads against the old Company File path gateway, was deleted with snapshot-v1 in the legacy sweep (B2b).

`CloudCompanyComputerAccess` provides owner/admin grant configuration and status recovery through a member-authenticated RPC adapter. Bind it to the exact office scope and staff ID, read `status()`, then submit the observed grant version and an explicit capability set: `["shell"]`, `["desktop"]` or `["desktop", "shell"]`. Existing grants keep their capabilities. SQL changes the set and version atomically, fencing old screen leases; a revoked grant does not prove physical drain. A lost response requires a status refresh. Browser access still requires the separate profile owner's consent. No client receives execution authority through it.

The root export is browser-safe. It includes sponsored session admission, exact run cancellation, native provider sign-in, Company File path validation, and computer wire contracts. Authentication is supplied by the client host. Login returns a scoped interaction capability, never a provider OAuth credential. The same sponsored turn RPC and authority checks apply to both client types.

`cloud-file-transfer.ts` defines explicit workbench exports, imports and immutable asset references. An import source is either an `object_storage` asset ID/hash or a `company_file` path and exact version observed through the governed file tools. Current runtime authorization checks the source before transfer; the destination is a separate relative `company_computer` path and is never overwritten. Company File import receipts retain an asset ID, manifest hash and content hash as historical provenance; workbench bytes remain mutable afterward. `CompanyFileAssetWrite` selects a completed export as the source of a governed `company_write`, using the same destination path/version and operation key as text writes. These browser-safe parsers expose no execution, storage credential or download authority. Member-selected uploads use the separate human command flow below. Worker transfers remain separate integration work.

`CloudMemberCompanyFileReader` provides shared member display reads and explicit `download({ realm: "company_file", path, version }, signal)` selection. Downloads return binary bytes with company/environment, exact path/version and manifest/content hashes after current member path authorization and Web Crypto verification. Every object uses the existing version-scoped member gateway; a final descriptor read refuses changed content or access. This API never accesses a local path. The object gateway now supports an explicit `QORPERA_MEMBER_CLIENT_ORIGINS` allowlist. `scripts/test-member-file-cors-browser.mjs` and `scripts/test-member-file-browser.mjs`, which ran this reader in Chromium against the snapshot-v1 gateway, were deleted in the legacy sweep. Hosted proxy/TLS configuration still needs acceptance.

Explicit `node/*` subpaths contain Node file/object adapters and the private-network screen-view transport. They are excluded from the browser entry. A browser uses an authenticated WSS gateway for viewing; the loopback TCP bridge is for Node hosts. Server execution and guest authority live in `@qorpera/runtime` and cannot be imported here.

Use `scripts/check-headless-packages.mjs` to verify both the source boundary and browser bundle. The Step 4 integration plan records which endpoints and adapters are ready and which still require implementation or live acceptance.

`CloudCompanyComputerBrowserProfiles` provides bounded owner-only profile pages, idempotent named registration with a caller-retained UUID, observed grant status and explicit consent changes. Consent uses both profile and grant versions; a recorded active grant may be unusable after membership or office changes. Registration does not prepare the browser, and physical preparation does not attest that a website login succeeded. Only the owner can authorize agent use after private preparation.

`CloudCompanyComputerViews.connectPrivate` requires the owner's exact privacy challenge, fresh private status and acknowledged screen drains. It connects private control without shared takeover; callers must explicitly reconnect. Closing a view never requests privacy exit. `CloudMemberBrowserRecovery` discovers only offices containing the account's own profiles and works independently of Company File membership. All these shared APIs remain browser-safe and contain no runtime execution or model credentials.

`SupabaseCloudPresenceTransport` is the shared presence transport. It uses native Web Crypto, ephemeral Ed25519 keys and the existing private, membership-authorized Realtime channel. Tracked threads, typing and member-reported attached-agent activity remain lossy; activity is not proof of an admitted native run.

`company-path-presence.ts` defines the separate native Company File observation protocol and relevant-path view. Its shared schema, canonical signing bytes and overlap rules are browser-safe. The runtime owns native signing identities and current path authorization; these functions grant no native authority to a member client.

`CloudMemberCompanyPresence` supplies read-only path activity to the web clients. Give each observer a dedicated, account-bound Supabase Realtime client: Supabase reuses identical topics within one client, and the observer owns/removes its channel. Supply the configured object-gateway origin, an account-bound token callback, a lifetime AbortSignal and an `onChange` callback. Call `select(paths)` with up to eight canonical paths, or `select([])` to clear. Selection and channel changes cancel old requests; account changes must abort the lifetime. `close()` removes only the observer's channel and never forgets a native identity.

The member gateway checks current readable paths, resolves admitted native identities through separate service transactions, verifies signatures and returns matching activity without binding, key or route-token metadata. Verified client/sequence confirmations prevent an older overlapping claim from reappearing after newer nonoverlapping work. Transport/candidate/body/participant limits, finite deadlines and local expiry keep this lossy display bounded. Unavailable or empty observations never lock a file, prove absence of other work or authorize an operation. The Company File UI displays the inspected file/folder and current known agent names; canonical reads, saves and review retain their own authority checks.

With `QORPERA_WEB_PRESENCE_TEST_BROWSER` set, `scripts/test-runtime-company-presence.mjs` (deleted in the legacy sweep) combines all migrations, real SQL, signed native Phoenix traffic, the member gateway and the member web package as the browser consumer. It verifies overlap, selection clearing and path revocation. Hosted Realtime and live deployment acceptance remain separate.

`scripts/test-cloud-presence-browser.mjs` runs the library in an isolated Chromium process using a synthetic channel and identity registry. Set `QORPERA_PRESENCE_TEST_BROWSER` to an existing Chromium executable. The proof exercises real browser signing, verification, publication and cleanup without Node globals or external network access; it does not test live Supabase authorization.

`CloudCompanyComputerStart` provides the start/status/cancel API to the web clients. The host supplies a member-authenticated RPC adapter; SQL requires owner/admin authority for mutations and membership for status. Retain a request UUID, observe the current office generation, and recover a lost response with `status()`. Multiple requests may return one existing intent. Cancellation records that preparation must stop; it does not establish guest drain or free capacity. A client disconnect performs no cancellation and owns no office lifetime. The API is implemented; client UI composition and physical provider activation remain in progress.
